# 個人資金繰りダッシュボード

みずほ銀行(本郷支店 普通4104341)の通帳スクショをもとにした個人資金繰りダッシュボード。
Vite + React のローカルアプリとして動作し、データはブラウザの localStorage に保存されます。

## 起動方法

```bash
npm install
npm run dev
```

ブラウザで http://localhost:5173 を開く。

本番ビルドは `npm run build`(`dist/` に出力)、確認は `npm run preview`。

## 機能

- **KPIカード**:最新実績月 / 月初→月末残高 / 当月CF / 予算ベース月次CF / 予測期間の最低残高(10万円未満で警告、マイナスで資金ショート警告)
- **残高推移チャート**(recharts):実績=濃色、予測=薄色、残高ゼロの赤点線。「実績のみ表示」トグルあり
- **データ検証**:残高連鎖(前月末=当月初)、月初+CF=月末、明細合計と取引後残高の連鎖、カテゴリ合計=出金 を自動チェックし、不一致を警告パネルに表示
- **予算設定**:固定費・変動費を項目ごとに追加/編集/削除。予測出金 = 固定費計 + 変動費計
- **予算 vs 実績表**:項目マッチングは記号除去して部分一致。予算外支出は自動検出
- **項目別 月次推移マトリクス**:行=項目、列=月、予算超過セルは赤。クリップボードコピー(スプレッドシート貼付用TSV)と CSV ダウンロード対応
- **取引明細テーブル**:月ごと、通帳と同じ粒度
- **月次資金繰り表**:実績+12ヶ月予測。実績行クリックで明細・内訳の表示月が切替
- **エクスポート**:月次サマリー CSV / カテゴリ別 CSV / 取引明細 CSV / 全データ JSON(すべて BOM 付き UTF-8、Excel・Google スプレッドシート対応)
- **JSON取込**:単月・複数月の配列・JSONバックアップ(`{months, assumptions}`)のいずれも取込可能。取込時に整合性を自動チェック
- **資産の分離**:楽天証券への入金と自己口座(ゆうちょ銀行 ミキ トモヒロ宛振込)への移動は「資産」区分として消費支出と分けて集計。予算にも「資産へ」枠があり、マトリクスには「うち資産へ」「消費支出(資産移動除く)」行を表示。通帳ベースの入出金・残高計算は変更しない(銀行から出ていくお金として月次CFには含まれる)
- **サブ口座(ゆうちょ銀行 ****581)**:`src/data.js` の `SUB_ACCOUNTS` に通帳から復元した月次残高・明細を保持し、資産セクションに残高推移・明細・判明資産合計を表示。主口座と同じルールで整合性チェック
- **テーブルのヘッダー固定**:各表は縦スクロール可能なコンテナ内にあり、ヘッダー行(マトリクスは項目列も)が固定される
- **トップビューの資産表示**:KPIに「現預金残高(みずほ+ゆうちょ)」「総資産(現預金+投資への純移動累計)」を表示。チャートにも現預金残高・総資産(緑破線)のラインを追加。資産への移動の明細セクションはページ最下部
- **単発支出(予定)**:予算設定内で「月・内容・金額」を登録すると、該当する予測月の出金に上乗せされ、残高予測・最低残高に反映。月次資金繰り表の該当行に内容を表示(実績月には影響しない)

## データモデル(月次レコード)

```json
{
  "month": "2026-06",
  "type": "actual",
  "rev": 2,
  "startBalance": 857907,
  "endBalance": 181305,
  "income": 804277,
  "expense": 1480879,
  "incomeDetail": { "給与(スポーツネーション)": 604277 },
  "categories": { "楽天カード": 643771, "家賃": 155000 },
  "transactions": [
    { "date": "06-01", "name": "ネット コン フミカ(仕送り)", "amount": -60000, "balance": 797907 }
  ]
}
```

- `transactions` は時系列昇順。`balance` は取引後残高
- 検証ルール:`startBalance + Σamount = endBalance`、`income - expense = endBalance - startBalance`
- カテゴリ合計 = `expense` が成立すること(不足分は「その他(未分類)」)

## 永続化と初期データのマージ

- 保存先:localStorage(キー `cashflow-dashboard-v1`)
- 起動時に `src/data.js` の `INITIAL_MONTHS` と保存データを月キーでマージ。`rev`(改訂番号)が新しい初期データは保存データを上書きする
- 通帳検証後の差し替えは、`src/data.js` の該当月に `rev: 2`(既存revより大きい値)を付けて更新する

## 運用フロー(毎月)

1. 月末に通帳スクショを撮影
2. Claude(チャット)に貼って明細を JSON 化・検算してもらう
3. ダッシュボードの「月次データ取込」に貼り付けて取込 → 実績追加、12ヶ月予測が自動更新
4. 取込時の検証警告が出たら、スクショと突き合わせて修正
